## Current pipeline contract (2026-10-02, supersedes historical windows below)

- The update window is one rolling **calendar month in Asia/Shanghai (UTC+08)**, including today's date and the corresponding previous-month date. Clamp to the previous month's final day, e.g. March 31 → February 28/29. A precise deposited online date takes precedence. Missing, year/month-only, invalid and future dates are excluded from ingestion/automatic analysis; none is replaced by discovery time. Existing historical papers remain stored and readable.
- Both Crossref and RSS use that window. **2026-10-04 superseding discovery contract:** use [latest-first ingestion](../docs/research-ingestion.md#最新优先与月内回扫2026-10-04). The first request for each 08/20 batch checks a fresh indexed-desc head even when old cursors remain. Use two passes across sources: first one request per source ordered by oldest `crossref.headPlannedThrough` (missing first); only then spend the remaining total request budget on pending sources ordered by oldest `crossref.lastContinuationAttemptAt`. Keep the same verified `batchKey` on both calls. At most two attempts/source/slot, at most 20 calls total, morning 260 seconds/evening 330 seconds for collection and overall 540-second soft budget; never drain a queue. Latest overflow and month-only reconciliation have separate cursors and truthful completion/expiry ledgers. Current-month records alone are processed, while historical stored papers remain untouched. RSS is capped to 150 actual recent entries.
- Each source sync also rechecks at most two eligible, oldest-checked stored DOIs directly against Crossref, excluding records already checked in that same sync. The recheck rotates across recent records independently of index watermarks. Exact DOI identity is required. Save real metadata diffs, versions, before/after provenance and retrieval times; unchanged retrieval is not counted as a metadata update. Preserve richer known fields if the new source omits them. Stable field precedence avoids alternating channel formatting invalidating analysis every run.
- Scripts do fetch, DOI/URL dedupe, normalization, field diff, controlled tags, existing relevance/reading-priority scores and triage. AI is gated only for multiple-topic ambiguity, explicit comparison/novelty/mechanism complexity in a relevant abstract, uncovered semantic keywords, or a user-preference match needing classification. Missing/short abstracts abstain. Easy records remain `rules_only`. This is a transparent versioned triage heuristic, not a completeness claim.
- The dedicated `POST /api/site/research/process` shared writer accepts only `{ "maxPapers": 0..3 }`. It uses the **existing owner-private Sites dispatch service boundary**, selects exactly one owner-created configuration, and refuses ambiguous/missing configuration. It never forges a visitor identity or exposes/reconfigures credentials. Identity-bearing browser requests must be the saved owner; same-origin browser posts require `X-HKIS-Request: 1`. Existing `/api/site/ai/*` owner checks remain intact. Recheck owner-private audience before every scheduled run; sharing this Site requires redesign/review of shared writer authorization.
- The processor loads current saved endpoint/model/protocol/reasoning and semantic preferences each run, requires enabled/key/connection-test eligibility, and rejects Kimi Code for unattended use. It performs at most 50 deterministic triage records and 3 single-paper model requests per call, with a 32 KB semantic input ceiling, under a 240-second soft processing deadline plus provider 90-second timeout. No tools, search or arbitrary mutations are exposed to the model. Output cap is min(current configured maximum, 8192) for this bounded assessment, without editing settings. All attempts share existing `ai_receipts` daily and six/minute budgets with interactive use; never raise daily limits. Remaining work persists in a queue.
- Content-relevant fields + semantic model/config/preferences + prompt/schema/rule versions form the durable cache key. Author/affiliation-only corrections do not rerun a semantic assessment that did not use them. Current content/config/schema must match for badges, counts and filters; stale assessments remain as versioned history but are not represented as current. No unchanged paid repeats. A durable claim and receipt precede sending; timeout/unknown/failed/invalid replies do not automatically retry. Budget blocks with no sent receipt can resume later. Credentials and provider output are absent from runtime logs.
- Persist AI decision, rubric, evidence adequacy, low/medium confidence, exact abstract quotations, semantic keywords/topics, provisional importance and **abstract method-evidence** scores separately from script scores and author keywords. Quote matching checks provenance, not entailment. Missing/unmatched evidence suppresses generated claims/scores. Abstract-only output is never scientifically verified paper quality, reproducibility or proof of novelty; JIF is excluded from single-paper scores. Read-only browsing never calls a provider.

## Sources and field semantics

See `research-config.ts` for the exact journal/ISSN/RSS allowlist. IEEE official RSS supplies title, ordered authors and actual abstracts when present. Crossref supplies publisher-deposited registry metadata with precise DOI identity and author-linked affiliations when available. Wiley/Elsevier RSS may be unavailable or return non-feed HTML; this is recorded as channel unavailability, never successful empty ingestion. OpenAlex only supplements exact DOI matches with missing abstracts or affiliations. Every field carries provenance and every source record has its retrieval time.

- Full author lists are retained. The first author means deposited `sequence=first`, or first listed author where order is the only evidence. Correspondence is displayed only when explicitly returned, with provenance.
- Author keywords are distinct from HKIS rule-derived topic labels. Crossref subject labels and OpenAlex inferred keywords are not imported as author keywords.
- Online/publication/print precision and registry date fields are retained in provenance. First discovery and last retrieval are separate. A future issue date is not called an already-completed publication date.
- Missing abstract/affiliation/keyword values remain missing. Rule priority is an explainable reading-order heuristic, not a scientific quality or AI judgment.
- Bibliographic metadata and actual available abstracts are retained privately; publisher full text, PDF, images, cookies and paid content are not fetched. Abstract copyright remains with the publisher/author. Reassess rights before changing the site audience.
