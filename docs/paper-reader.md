# 论文已读与收藏

论文库、论文日报、研究进展、每周热点、详情和跨库检索中已入库的论文共用阅读状态。旧 `/items` 订阅内容的本机收藏继续保留在收藏页的独立折叠区，不把旧 RSS ID 误认成论文 ID。

## 操作

- 成功打开可见的论文详情后自动设为已读；从论文卡片点击 DOI / 出版商原文（含键盘、Ctrl/Command 点击和鼠标中键）也异步保存已读，不阻塞跳转。服务器渲染、预取、悬停、勾选、收藏操作均不设为已读。外部站点是否成功载入无法由本站确认，已读依据明确的打开动作。
- 已读卡片用更安静的底色和次级文字呈现，保留清晰标题、收藏标识和键盘焦点；不用整卡透明度或阴影。浅/深主题沿用有对比度约束的语义颜色。
- 论文列表上方可全选当前页、手动多选、清空选择、批量已读或设为未读。显示已选数及范围；翻页或更改筛选清空选择，不改变筛选与分页。不提供暗含全库范围的全选。
- 条目右上角可收藏 / 取消收藏。已收藏以书签和文字双重标识；侧栏「收藏」进入账户论文收藏，每页 24 篇。移除后当前列表暂留该条，可刷新查看最新集合。
- 保存失败撤回尚未保存的乐观状态并给出提示；可再次点击操作。刷新、重新进入或跨设备会读取数据库，浏览器本地存储不是论文状态来源。切回窗口时重读已见论文状态。

## 持久性与身份

新增 `paper_reader_state`，复合主键为 `owner_id,paper_id`；`read_at` 和 `favorite_at` 独立存储，可分别清除。关联持久化的 `research_papers.id`，不在客户端重新计算 DOI 哈希。RSS 先入库、后补 DOI 的论文继续使用原有 ID；学术服务精确身份匹配后的补缺沿用该 ID。端点还接受当前论文表中精确 DOI（含 doi.org URL / DOI: 前缀）作为别名并返回规范 ID；不从可能冲突的来源证据或近似题名推断身份，不引入论文合并。

仅新增独立表、外键和按所有者/收藏时间查询的索引；不更改论文、来源、评分、分析、模型配置、凭证、定时任务或旧本机数据。迁移由 Drizzle 生成、发布时增量应用。

## API 与安全

- `GET /api/site/research/reader-state?id=…`：每次 1–100 个标识，返回规范 ID、已读时间、收藏时间；没有写入
- `PUT /api/site/research/reader-state`：`ids`、`field`（read / favorite）与布尔 `value`，显式设置值，支持幂等重试；验证全部 ID 后事务批量 UPSERT，只更新指定字段
- `GET /api/site/research/reader-state/favorites?page=1`：当前账户收藏的完整论文数据及分页
- 每次先验证 Sites 可信身份和本站所有者；平台服务令牌不代替用户身份。写入必须同源、JSON 与 X-HKIS-Request 头，正文有 24KB 上限；SQL 参数化，不接收客户端 owner ID
- 返回 private,no-store，禁止共享缓存；错误不输出私密状态或原始数据库错误。模型与工具没有访问此写接口的能力
- 客户端同一页面挂载的查询合批、单请求不超过 100 篇；写入按触发顺序提交，已确认状态与待保存动作分离，旧读取结果不覆盖新动作。若超过 100 篇的可见列表分批保存且后续失败，已成功批次保留，失败批次撤回并提示失败

## 复用

`PaperReaderProvider` 在应用根节点提供状态。列表用 `PaperSelection ids={当前页真实论文ID} scopeKey={筛选+页码}` 包住，并在列表标题处放 `PaperBulkToolbar`。卡片用 `PaperCardState id title`；外部论文链接用 `PaperSourceLink paperId`，不要把期刊指标链接当作打开论文。详情用 `PaperDetailState`，它只在成功的可见客户端挂载时自动设为已读。普通内部详情 Link 不在预取/SSR 中写入。

## 验证

`node --test sites/paper-reader-client.test.ts` 验证合批、幂等、清除、并发顺序、迟到读取、保存失败回退与分批失败边界。`node sites/test-reader-worker.mjs` 使用隔离的真实 Worker/D1 和合成身份/论文，验证迁移、所有者/CSRF、100/101 边界、DOI 别名、补 DOI 保持身份、批量原子性、收藏分页、无阅读时写入及来源/分析不变；阻止所有外部请求。不要为了测试在生产库批量标记论文或生成真实模型请求。

## 完整列表只读批量查询

`POST /api/site/research/reader-state/batch` 仅查询状态，不修改任何表。与原读写接口一样，每次验证Sites可信身份与所有者；额外要求同源Origin、JSON、X-HKIS-Request与允许的Sec-Fetch-Site。只接受 `{ids}`，原始数组1–2000项、每项沿用240字符边界，按字节读取最多512 KiB（不信任Content-Length）。先完整解析所有别名，任何缺失都原子404；再以所有者和JSON绑定数组查询状态，最多两次SELECT，避免D1参数数量上限，不为每篇发查询。

原GET及PUT仍是1–100项，PUT仍限24,000字节；写入队列、幂等/回滚、单列更新和收藏范围不变。浏览器同一轮聚合超过100个缺失状态时用新POST，每批最多2000，所有读取共享最多3路并发。卸载一个订阅不取消其他订阅共用的只读请求；传输AbortError/失败会清理加载记录，显式重试。读取开始时已有pending写入的ID及后续版本变更均不能被旧响应覆盖。卡片和收藏按钮复用同一状态订阅，范围匹配用Set；全量DOM与全选语义保留。
