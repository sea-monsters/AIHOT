# 每日 AI 论文日报

`/daily`、`/daily/archive` 与 `/daily/YYYY-MM-DD` 共用真实、持久化的日报归档。只展示选中一天；月历默认 UTC+08 当前月，可输入年份、选择月份、前后翻月和返回本月。标记的是已有日报/空档/待处理归档，不将有论文的日期冒充已生成日报。刷新、切换日期、阅读来源和收藏不触发模型。

## 日期、选择与证据

- 日报日期 D 汇总 D−1 当地自然日 00:00–24:00 内、明确归属 08 / 20 点采集批次的首次新增论文，时区 Asia/Singapore（UTC+08）。发表日期不用于归档归属；后续补摘要、作者或其他元数据不算新论文。
- 两个批次按实际 batch key、每个来源的 run ID、开始/结束、成功/部分失败、未尝试来源保存。17 个配置来源各有独立抓取记录；并非看到一个成功请求就声称完整跑完两次。
- 先生成前一日日报，再进行 D 日 08 点采集；同时以批次归属、首次入库时间和固定午夜截止防止 08 点竞态。相同首次入库日内的明确批次补缺可更新该日证据快照，跨日更新不能进入旧日报。
- 现有「阅读优先级」即 research_papers.priority，严格 >75。选中时保存分数、规则版本和依据。相关度、AI 重要性、AI 摘要方法证据分以及期刊影响因子均不替代此门槛。AI 分数尚未完成不意味着现有规则分未知。
- 脚本做去重、门槛判断、关键词主归组与分块；同一论文只进入一个主关键词组。优先取已定义的领域关键词，其次作者关键词/研究方向；每段最多 3 篇论文。AI 只负责摘要进展描述。
- 每段完成态文字必须为 200–300 个汉字，按 Unicode Han 计数，标点、拉丁字母、数字和引用不计数。每句绑定唯一真实论文 ID 和实际摘要连续引用，引用 15–220 字符且至多 25 个空白分隔词；数值必须存在于该句引用，重复句、错误 ID、未涵盖输入论文、长度越界均不发布。模型不得生成作者姓名/题名，引用与作者由服务端源数据提供。
- 没有或过短摘要、证据不足、超限和未确定规则分分别显示；不填充虚构突破、不由标题推论实验结果、不跨论文混合结论。连续引用检查不是自动语义证明，更不是全文、可重复性或科学质量核验，页面明确提示核对。
- 报告中没有任何 >75 分新论文时明确显示无达标内容；缺失批次时标记覆盖不完整，不能由不完整记录推断当天没有论文。旧记录缺少批次关联时计入「未追踪入库」，不追溯伪造归属，也不付费回填历史。

## 持久性与成本

D1 新增 research_batches、research_batch_members、research_daily 和 research_daily_groups；research_runs 仅新增 nullable batch_key。旧迁移不变，论文、阅读/收藏、模型配置和原采集记录保留。

每日报 date 主键、修订 1、截止、选中 ID、覆盖、内容 hash、schema/prompt 版本、创建/更新时间和完成状态持久保存。分组另存输入快照、hash、模型/协议/思考等级/设置 revision、输出、来源 ID、request ID 与错误代码。历史快照不随模型或元数据修改重写；没有隐含重新生成按钮。

每次最多 2 次模型请求；按执行的本地日期查询共享回执，重复触发同一天也最多 2 次实际尝试。一次最多 6 段、64,000 字节证据输入、8,192 输出 tokens（仍受用户保存的更小上限限制），90 秒供应商超时，总日报操作约 190 秒。单日报最多准备 240 篇 / 80 段；超过容量明确计数，不静默丢失；这些论文仍在论文库，归档不会自动扩容重跑。摘要单篇输入上限 20,000 字节。

完成的分组复用；尚未发送的分组可在后续 08 点继续，优先最早排队日报。预算不足没有回执时可恢复；已发送失败/结果未知的请求不自动重发。中断后先核对持久回执，已收到响应可无收费恢复解析；不确定状态转为待核对，不永久伪装生成中。打开页面不会让后台继续工作。

所有收费请求经过现有 providerCall 和 ai_receipts，每日额度与助手、选择性论文评估共用，额度和重置口径保持原配置（现有共享每日计数按 UTC），不提高上限。使用调用时当前保存且连接测试成功的模型，保留思考等级；禁用、缺 key、未测试或 Kimi Code 均阻断无人值守模型调用。没有额外 key、自动降级或换供应商。

## 唯一现有定时任务的 HTTP 契约

不要另建定时任务。沿用已有 Asia/Singapore 08:00 / 20:00 的 Site automation；仅 08 点调用日报。服务器额外拒绝 08:00–08:59 以外的日报开始请求。本文代码提供端点，不自行变更外部调度；实际关联/启用以设置镜像和平台任务回执为准。

每天 08 点：

1. POST /api/site/research/daily/generate，JSON {"maxCalls":2}。服务端固定当天及前一天截止，客户端不得指定日期、owner 或模型。日报最多 190 秒；网络结果未知不要重复调用。它会创建当日归档，并在余下预算内继续最早已存排队分组。
2. POST /api/site/research/batch/start，JSON {"slot":8}，保留 batchKey。若返回已 finished，不重新采集此批次。
3. 读取 /api/site/research/status，按最久未检查的来源顺序串行 POST /api/site/research/sync，JSON {"sourceId":"实际ID","maxPages":1,"batchKey":"步骤2返回值"}；仅当明确 pending 且时间充裕可同来源第二次，maxPages≤2。保留原最多20请求/每来源最多2次上限。切勿为了赶齐17来源虚报成功。
4. 在采集阶段约260秒内停止新请求；同时遵守整个自动化540秒软预算（给10分钟平台上限留60秒）。每步之前检查已用时间；余量不足110秒时不开始新的长请求。能完成的请求先结束并记录实际状态。
5. POST /api/site/research/batch/finish，JSON {"batchKey":"实际值"}，即使没抓完也结束此次批次并如实显示缺失来源。随后仅在总剩余≥110秒时 POST /api/site/research/process，JSON {"maxPapers":1}；不够就跳过并说明评估待后续处理。

每天20点：不调用 daily/generate；先 start {"slot":20}，同样逐来源 sync + batchKey；采集阶段≤330秒，结束批次；剩余充裕时 process {"maxPapers":2}。总软预算同样540秒，给HTTP与平台收尾留余量。单个来源采集请求的网络阶段共享75秒截止（每个外部请求仍最多25秒），到期后记录已完成部分与剩余缺口；处理和数据库收尾仍需HTTP余量。实际长请求可能提前耗完预算，停止后保留已提交数据、游标和真实覆盖。

08点给日报预留调用时间，因此上午采集预算从原6分钟缩为约260秒、选择性评估从最多3篇缩为最多1篇；20点评估最多2篇。这会造成部分信源或 AI 评估排队，页面如实呈现，不能宣称所有来源在每个时段必定完成。

确认平台提示词已更新后，POST /api/site/research/schedule 沿用原 id、enabled、schedule、timezone、nextRun，再增加 dailyEnabled:true、dailyContractVersion:"hkis-daily-v1"。未完成提示词更新前不要写已启用镜像。此端点只保存回读镜像，不修改真实自动化。

所有请求均经既有私有 Site dispatch；有浏览器 Origin 时写请求另需同源和 X-HKIS-Request:1。不把服务令牌放在提示词、源码或日志。
