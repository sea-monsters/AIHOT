# 覆盖不完整：指标与本地修复边界

## 指标不能混为一谈

- 头部检查：本轮实际尝试了来源的最新索引窗口，不保证该窗口所有分页已读完。
- 当前待处理窗口：latest/history 中仍 pending 的扫描；每页最多100条，记录筛选与实际HTTP页数不同。
- 连续历史水位与 expiredIncomplete：历史未完成窗口留下的缺口，累计的是窗口而不是论文篇数。当前 pending 清零不能清除这些证据。
- 35页是整轮持久预留的 Crossref 尝试额度，失败也占用；60 calls 是 source 调用额度，包含本地持久片处理，不是60次外部抓取。
- 32源、35页且尾部约8页优先续抓时，不能保证同一窗口所有32源首次检查；头部按最近实际尝试时间轮转，续抓有独立轮转。未改变此预算取舍。

## 可复现的本地问题与窄修复

1. 已完成整月history原先在每个新slot因队列为空而重新建立，重复竞争有限页额度。现在整月复核的最早重开时点为最近计划/完成证据后7日，且仍须history为空并进入新cycle。首次整月、每日新增出版日期、最新索引窗口、已开始游标均保留；不是永久取消复核，也不承诺每7日一定执行。旧JSON从整月job或完成ledger恢复时点，缺证据时保守建立一次后持久记录。历史缺口不会被重置。
2. 单slice每源两次的公平上限曾在仍有可处理持久片时返回no_dispatchable_source。现在只有已观察到明确持久进展、所有候选仅因该slice上限被挡且新鲜control仍允许persist时，返回已有可续slice边界。无进展、未知、错误、活动锁、全局停止保持原处理；35页、60calls与原截止均不放宽。

这些缺陷的本地复现不等于已证明每个生产partial都由它们导致。上游429、HTTP/连接异常、真实时间预算、历史积压仍须按对应批次证据分别归因。源级最新error可能早于当前批，不能拿它替代冻结的批次结果。

## 验收与发布限制

专属测试、固定预算多周回放、真实collector/control/runner及持久入库链路分层验证；合成回放不是生产吞吐证明。生产不补跑、不手动重抓、不绕过403/429、身份或平台安全边界。完成测试及独立审查前不发布；修复不承诺每窗完整覆盖全部文献目录。
