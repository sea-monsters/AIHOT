# PostgreSQL 测试安全隔离：待实现方案

2026-11-13 对候选与 `aa2bbdf` 基线分别使用 Node 24.22.1、独立 PostgreSQL 17 空库、35 项迁移及关闭的安全阀运行，均为 156/183，27 个失败名称一致。22 项直接因 `chatJson` 的模型安全阀关闭抛错；其余五项需要单独验证：回执重试期待两次 stub 请求而实际零次；signal 测试在嵌入不可用时提前返回且未写 decision；三项翻译测试分别因没有请求、缺少译文记录和引用数为零失败。不能在未经模型替身的对照下把后四项全部定为同一根因。

测试现状存在前提冲突：测试套件把模型请求配置到本机 HTTP stub，却要求产品模型入口在 `MODEL_CALLS_ENABLED=false` 时工作；部分子进程、default-model、alerts 等测试还显式设置 true，`receipts.test.ts` 修改运行时模型配置。为通过测试而开启环境开关、覆写生产 guard 或偷偷跳过这些测试都不符合验收。

建议先将业务流程的模型和嵌入依赖抽成显式注入接口：正式构造路径仍只使用原 `chatJson`/embedding 提供者，关闭时在任何凭据、回执及网络派发前拒绝；测试构造路径使用测试目录内纯内存替身与合成响应，不引用真实 provider、凭据或网络。将回执、解析、预算的纯逻辑按可注入的无网络 transport 分层测试；避免导出带真实网络实现的绕过 guard 入口。对需要本地 HTTP 故障的测试，使用只供测试构建的 transport、一次性空库和网络隔离容器，凭据全是测试值；不能以模拟 adapter 的成功断言正式 provider 已联网或生产安全阀通过。

逐一移除测试及子进程对真实安全阀的开启或配置对象改写；测试开关开启/关闭的业务状态时，注入独立的合成状态源，而非改真实运行环境。新增未修改正式 provider 的安全测试，证明阀关闭时 chatJson 拒绝、embedding 不可用且 fetch 为零；再针对上述五项用 fake 精确检查决策、引用、预算、ACK 和取消。分别报告安全阀原路径测试、合成行为测试、网络隔离及任何跳过/失败。完成这些改造并在全套与 v124 前向移植上验证前，不得称 PostgreSQL 套件已通过。

## 可执行的安全复现

`HKIS_NODE_BIN=/absolute/path/to/node bash scripts/test-postgres-isolated.sh` 使用独立 PostgreSQL 17 容器，`--network none` 仅保留容器内回环；仓库以只读方式挂载，数据库是一次性 `hkis_test`，所有安全阀显式为 false，未传入外部凭据。迁移完成后原样运行现有 PostgreSQL 套件，退出时销毁测试容器和数据库。Node 24.22.1+ 与可用本地 Docker daemon、现有项目依赖是前提。

测试专用 preload `tests/fixtures/closed-safety-valves.mjs` 拒绝进程内和继承 preload 的子进程开启或删除这些环境开关，并拒绝直接把真实运行配置改为 enabled。它只增加限制，不修改生产源码、不替换 provider、不抑制测试失败。现有假设开关可开启的测试会明确报错，直到改为注入合成模型/状态依赖。容器无外网也不能证明所有业务测试已通过；必须保留退出码与失败清单，并另行验证真正的依赖注入。

2026-11-13 本次以 `560bfbff9be5b5257f06434316aa96be32534a13` 加测试隔离入口运行：Docker 明确检查 `network=none` 和容器内接口仅 loopback，35 项迁移完成；带强制关闭防护的 PostgreSQL 套件为 130/184，通过 130、失败 54、跳过 0。该次早期 preload 提前导入了配置，改变了若干与安全阀无关的测试初始化时机，因此不能把 130/184 与 156/183 直接比较；它也暴露了测试在进程、子进程和配置对象中尝试开启安全阀的依赖。随后 preload 已改为在配置自然加载时添加只收紧、不启用的保护。隔离入口与安全阀测试通过不代表 54 项已修复，也不能证明模拟注入完成或允许上线。


## 已实现的合成依赖与本次结果

`npm run verify:hkis:postgres:sim` 在 `--network none`、临时空 PostgreSQL 17 库和 Node 24.22.1+ 下运行完整 `tests/*.test.ts`。测试专用 loader 只在隔离容器、显式模拟模式和安全阀 false 时装载：将指定业务调用处的模型与嵌入依赖替换为测试目录中的纯内存替身；跨子进程的模拟模型仅访问容器内明确的 127.0.0.1 stub 和固定测试密钥，不跟随外部地址。正式模型模块及其 guard 的源码没有修改；独立测试直接调用原入口，确认阀关闭、fetch 为零、真实通知配置关闭。

测试专用配置替身和隔离 loader 的合成状态用于覆盖通知、反馈及告警开关的业务分支；它们不会修改真实环境阀或正式配置。对应 Feishu/告警代码是在测试进程内的合成副本，实际生产阀关闭路径单独检查；不得将模拟发送、费用回执或模型回答表述为真实发送、费用或 provider 验证。所有子进程继续继承关闭阀的 preload，尝试开启真实阀时直接失败；测试仓库只读挂载，临时 `.data` 在容器 tmpfs 中，退出时容器和数据库删除。

最终隔离模拟全套 184/184 通过、失败和跳过均为零；原先普通关闭阀模式下的 27 个失败名称均在 37 项核心模拟分组中通过，子进程停机和评测模拟分组 11/11、通知模拟分组 14/14 通过。测试替身覆盖业务编排和真实的本地 PostgreSQL 回执事务，但不证明正式 provider 在开启时的 HTTP 语义、付费服务可用、生产采集或真实网关取消。标准无替身关闭阀运行与模拟全套应分别报告，不得把后者标为真实 provider 全链路验收。
